# Power BI project

This folder contains an authored native **PBIP** project with a **PBIR** report definition and an import-mode **TMSL semantic model (`model.bim`)**. It also includes standalone Power Query M, DAX reference measures and a theme.

The report has three pages and shared Home and Date slicers on each page:

| Page | Contents |
|---|---|
| Overview | Commands, success rate, P95, heartbeat delivery, daily success trend and failure reasons |
| Reliability | Firmware slicer, firmware success, acknowledgement latency by source and device detail |
| Estimated energy | Consumption, baseline, modeled difference, cost difference, daily comparison and load breakdown |

## Open and refresh

1. On a Windows machine with current Power BI Desktop, run the Python pipeline from the repository root first.
2. Open `powerbi/SmartSwitch.pbip`. Alternatively open `SmartSwitch.Report/definition.pbir`.
3. In Transform data → Manage parameters, set **DataFolder** to the full `data/processed` path, for example `C:/Projects/smartswitch-analytics/data/processed`. Forward slashes make the example easy to copy.
4. Apply and refresh. If asked for file privacy settings, choose the setting appropriate to your own local demo files.
5. Check Model view. The two fact tables should have many-to-one relationships to `dim_device`, `dim_date`, and `dim_firmware`. Each relationship filters from the dimension to the fact.
6. Verify the Overview cards against `reports/summary.json`: **91,867 commands, 98.01% success, 614.4 ms P95, 99.21% heartbeat delivery**.
7. Try the Home and Date slicers. Check both command and energy measures respond. Firmware uses `dim_firmware`, so it filters both facts.
8. Optionally import `theme.json` through View → Themes → Browse for themes. The authored report uses the built-in base theme until this is applied.
9. Save in Desktop. Export a `.pbix` or PDF if needed and capture real report screenshots for the repository. Do not label `reports/dashboard.svg` as a Power BI screenshot; it is generated by Python.

Power BI Desktop was not available in the preparation environment. The PBIR JSON files were checked against Microsoft schemas, but successful Desktop opening, refresh, DAX execution, rendering and interaction remain native application checks. Keep this limitation until those steps have passed. No `.pbix` is claimed as already validated.

## Model and measures

- `dim_device`: device, home, room, load rating and assumed baseline runtime.
- `dim_date`: unique day, month, weekday and weekend flag.
- `dim_firmware`: the three demo firmware versions.
- `fact_command`: one validated logical command.
- `fact_device_hour`: one device-hour, with expected and received heartbeats.

Fourteen measures are included. `P95 Ack ms` uses **nearest-rank P95**, matching Python and SQL, rather than Power BI's interpolated percentile function. It selects the first `CEILING(0.95 × N)` successful commands ordered by latency and command ID, then takes their maximum latency. The unique command ID breaks ties deterministically.

`Assumed Baseline kWh` uses the visible device rating and baseline daily hours for each selected device-hour. `Modeled Cost Difference INR` uses the configured assumed flat tariff. Rebuild the assets after changing that tariff if you want the native DAX constant updated.

## Rebuild or construct manually

`python3 scripts/build_powerbi.py` rebuilds the authored native assets from the supplied report specification. It overwrites generated report definitions, so do not run it over manual Desktop changes you want to keep.

If your Desktop release cannot load the project, create a blank report, add a Text parameter named `DataFolder`, and create the four CSV queries in `PowerQuery.m`. Add a fifth query for the firmware dimension using the literal table in `model.bim`. Recreate the six relationships and add measures from `Measures.dax` through New measure, using `Name = expression` in the formula bar. The `:=` separators in the reference file are documentation syntax.

Recreate the visual field assignments using the table above and the `visual.json` field bindings. Save as PBIP for source control. Avoid joining the two facts directly.

## Native acceptance checklist

- Refresh completes with zero query errors.
- All five tables appear with the expected row counts and types.
- Six relationships are active with single-direction dimension filtering.
- All 14 measures evaluate without errors.
- Overall metrics match the Python JSON within displayed rounding.
- Each Home, Date and Firmware selection filters the intended facts.
- Date charts sort chronologically and percentage axes display as percentages.
- Failed commands are absent from latency calculations, not represented as zeros.
- All visuals have readable titles and show the synthetic-data context in the page names.
- Save, close and reopen successfully before claiming native validation.

The source-controlled format follows [Microsoft's PBIP documentation](https://learn.microsoft.com/en-us/power-bi/developer/projects/projects-overview) and [PBIR report definition documentation](https://learn.microsoft.com/en-us/power-bi/developer/projects/projects-report).
